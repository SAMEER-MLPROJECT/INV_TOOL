# Limitations

AttackGraph Lens is a competition prototype. These limits are stated so that evaluators and future users do not
over-read its results.

## Assumptions

- Source clocks agree within the configured skew (default 120 s). Larger drift can make real sequences look
  impossible or vice versa.
- Two path steps more than the configured gap apart (default 6 h) are not treated as one chain. Slow campaigns need a
  larger value.
- An IP is attributed to a host only through the asset inventory, which is assumed current. There is no DHCP-lease
  history, so an IP reassigned mid-window would be mis-attributed.
- Identity resolution is limited to case, domain-prefix/suffix and FQDN normalisation. Different accounts belonging
  to one person, or SID ↔ name mapping, are not resolved.
- Suspicion comes from source severities and alerts. The engine does not detect attacks on its own; it organises and
  explains what the sources report. A missed alert upstream stays missed.
- Criticality comes from the inventory. Assets missing from it default to 1 (3 for databases).

- Multichannel "corroboration" means independent activity on the same entities within ±15 minutes, not proof that two
  channels saw the identical action; a "silent" channel may be benign.
- The MD deviation baseline needs history (≥ 20 records for a pair, ≥ 30 for a relationship type) and assumes the
  baseline period is mostly benign; it is never used on its own to label anything suspected.
- Containment plans assume an action stops every later interaction of the contained entity at once, ignore business
  dependencies beyond the listed disruption costs, and are greedy (not guaranteed minimal).

## Synthetic-data limitations

- All demonstration and test data is synthetic, generated by a script that knows the answers. It shows the behaviour
  is correct on designed cases; it says nothing about detection performance in a real enterprise.
- One intrusion, ~1,200 events, ~350 entities, 3 days. Real environments are orders of magnitude larger and noisier.
- Log formats are simplified versions of common sources, not exact Windows Security, Sysmon, Zeek or vendor schemas.

## Incomplete integrations / unverified deployment modes

| Item | Status |
|---|---|
| Neo4j / AuraDB adapter | Implemented; tested only against a recording fake driver. **Not validated on a live database.** Neo4j partner-track eligibility is not claimed. |
| Docker image / docker-compose | Files provided; **not built** in the build environment (container registry blocked). |
| GitHub Actions CI | Workflow provided; **not executed** on GitHub. |
| Native log connectors (SIEM APIs, Syslog, Kafka) | Not implemented; ingestion is by file. |
| MITRE ATT&CK mapping | Technique IDs are displayed when alerts supply them; no automatic mapping. |

## Operational limits

- Live mode recomputes the full graph per micro-batch (≤ every 0.4 s). That is ≈ 30–90 ms at the sample's scale;
  millions of events would need incremental graph updates or moving traversal into Neo4j. Native connectors (Syslog,
  Kafka, vendor APIs) are not included: sources must POST JSON batches to the stream endpoint.

- In-memory, single-process state: data is lost on restart; one dataset per server; no concurrent multi-user
  isolation.
- **No authentication or authorisation.** Run bound to `127.0.0.1` (the default) or behind an authenticating proxy.
  No TLS termination.
- Graph view is capped at 600 nodes; path search at 8 hops, a 50,000-expansion budget and 3,000 candidates. Results
  say when they were truncated.
- Correlation compares seed pairs inside the window; performance on very large alert volumes is untested.
- Benchmarks were measured on the small synthetic dataset only.

## Areas needing real enterprise data

- Calibrating ranking weights and the suspicion threshold against labelled incidents.
- Measuring false-positive load of the correlation rules and the hub thresholds.
- Choosing realistic skew and gap defaults per source type.
- Scale testing (millions of events, tens of thousands of hosts) and deciding which work must move into Neo4j.
